# yoniverseproductions.com

Source for the portfolio page live at **https://yoniverseproductions.com/our-work**

There is no framework and no component tree. The entire page is generated by one Python
script, `build_site.py`, which holds the markup, the CSS, and the copy.

## Layout

```
build_site.py          the whole site: markup, CSS, copy, and both build modes
deploy.sh              rebuild and push live in one command
make_wm.py             regenerates the watermark overlay (wm.png)
wm.png                 the diagonal lattice watermark burned into every video
vid/wm/                the 16 watermarked spots (All Heart ah1-ah10, Handyman Dan hd1-hd6)
post/                  poster frames cut from the watermarked videos, plus the YouTube thumbnail
fonts/                 Onest + Archivo woff2, latin subset, both SIL Open Font License
yoniverse-work/        the Vercel project folder (holds the .vercel link, do not delete)
site.html              single file build, only used for the private Claude artifact copy
```

## Building

```bash
python3 build_site.py          # one self-contained file, everything base64 inlined (13MB)
python3 build_site.py web      # deploy/our-work/ with external assets (90KB page + 10MB assets)
```

The web build is the one that goes live. It is roughly 150x lighter on first paint because
the video loads on demand instead of being inlined.

## Deploying

```bash
./deploy.sh
```

That rebuilds, syncs into `yoniverse-work/`, and pushes to production.

Vercel details: team `yoni-paz-s-projects`, project `yoniverse-work`, domain already attached.
The CLI is not installed globally, a global npm install fails with EACCES, so everything uses
`npx vercel@latest`. Auth lives in `~/.local/share/com.vercel.cli/auth.json`. If it ever says
logged out, run `npx vercel login`. Logging in on vercel.com does not carry over to the CLI.

The apex domain still returns 404 because there is no main site yet. When one is built, add it
to this same Vercel project so `/our-work` keeps working.

## Things that will bite you

**No em dashes or en dashes.** The build asserts on it and fails. Yoni reads them as an AI tell.
Use commas, colons, or parentheses.

**Output must be pure ASCII.** The artifact host owns `<head>` so no charset can be declared.
Use HTML entities, for example `&middot;`. The build asserts on this too. Both checks run before
anything is written, so a bad build fails instead of shipping.

**Asset paths must stay root absolute** (`/our-work/a/x.mp4`). Vercel serves `/our-work` without
redirecting to `/our-work/`, so relative paths resolve against the site root and 404. This already
broke every video on the site once.

**Keep the watermark.** Every video carries a burned in diagonal watermark reading HOME SERVICE
STUDIOS and YONIVERSE PRODUCTIONS. The requirement is that this portfolio is the only place that
footage lives, so any re-encode must composite `wm.png` again. Masters are in
`~/Downloads/Final Deliverables - {All Heart Commercials, Handyman Dan}`.

**There are two video sets, and the build picks one.** The web build uses `vid/wm720/` at 720p
(44MB total) because assets are served separately. The artifact build uses `vid/wm/` at 360p
(10MB) because it inlines everything as base64 under a hard 16MB page cap. `build_site.py`
selects between them on `MODE`, so do not point both at the same folder.

Re-encode recipe, from the masters. The watermark must match the output height:

```bash
python3 make_wm.py wm720.png 1280 720          # lattice scales with the frame

ffmpeg -i MASTER.mov -i wm720.png \
  -filter_complex "[0:v]scale=-2:720[v];[v][1:v]overlay=0:0" \
  -c:v libx264 -crf 30 -preset slow -pix_fmt yuv420p \
  -c:a aac -b:a 96k -movflags +faststart OUT.mp4
```

For the 360p set use `wm.png`, `scale=-2:360`, `-crf 36`, `-b:a 48k`. Poster frames in `post/`
are cut from the 720p set at 35 percent through each spot, 640px wide. Watch out: the `sam*.jpg`
thumbnails in `post/` are YouTube stills for the Sam Halaby grid, not poster frames, so a poster
regeneration loop must not overwrite them.
